# TimeBlock 多端开发引导文档

> 本文档总结 Capacitor 迁移后的开发注意事项、最佳实践和开发引导。
> 
> **适用范围**：功能修改、新功能添加、公用代码开发

---

## 一、核心原则

### 1.1 多端兼容优先

**原则**：所有新功能和修改必须考虑三端兼容（Electron / Capacitor / Web）

| 平台 | 优先级 | 典型场景 |
|------|--------|---------|
| **Electron** | P0 | 桌面端主要使用场景 |
| **Capacitor** | P0 | 移动端主要使用场景 |
| **Web** | P1 | 浏览器预览和测试 |

### 1.2 平台适配层使用原则

**强制要求**：所有涉及平台差异的代码必须使用适配层

```javascript
// ❌ 错误：直接使用 localStorage
localStorage.setItem('key', 'value')

// ✅ 正确：使用适配层
import { storage } from '@shared/platform'
await storage.set('key', 'value')
```

## 二、功能修改注意事项

### 2.1 存储相关修改

#### ❌ 禁止事项

1. **禁止直接使用 localStorage**
   ```javascript
   // ❌ 错误示例
   const theme = localStorage.getItem('theme')
   localStorage.setItem('theme', 'dark')
   ```

2. **禁止在 Store 初始化时同步读取存储**
   ```javascript
   // ❌ 错误示例
   const storedValue = localStorage.getItem('key') // 同步调用
   const state = ref(storedValue)
   ```

#### ✅ 正确做法

1. **使用 storage 适配层**
   ```javascript
   import { storage } from '@shared/platform'
   
   // 异步读取
   async function loadData() {
     const value = await storage.get('key')
     state.value = value
   }
   
   // 异步写入
   async function saveData() {
     await storage.set('key', newValue)
   }
   ```

2. **在组件 onMounted 中初始化**
   ```javascript
   import { onMounted } from 'vue'
   import { storage } from '@shared/platform'
   
   onMounted(async () => {
     const theme = await storage.get('theme')
     applyTheme(theme)
   })
   ```

### 2.2 数据库相关修改

#### ❌ 禁止事项

1. **禁止直接调用 Electron IPC**
   ```javascript
   // ❌ 错误示例
   const result = window.electronAPI.dbQuery(sql, params)
   ```

2. **禁止使用同步数据库操作**
   ```javascript
   // ❌ 错误示例
   const result = db.querySync(sql) // 不存在同步方法
   ```

#### ✅ 正确做法

1. **使用 database 适配层**
   ```javascript
   import { database } from '@shared/platform'
   
   // 初始化（应用启动时调用一次）
   await database.init()
   
   // 查询
   const blocks = await database.query(
     'SELECT * FROM time_blocks WHERE date = ?',
     ['2024-01-01']
   )
   
   // 写入
   const result = await database.run(
     'INSERT INTO time_blocks (title, date) VALUES (?, ?)',
     ['任务1', '2024-01-01']
   )
   ```

2. **事务处理**
   ```javascript
   await database.transaction(async () => {
     await database.run('INSERT INTO ...')
     await database.run('UPDATE ...')
   })
   ```

### 2.3 文件导出修改

#### ✅ 正确做法

```javascript
import { filesystem } from '@shared/platform'

// 导出数据（自动适配平台）
const data = JSON.stringify(blocks)
const result = await filesystem.writeFile('timeblock-export.json', data)

if (result.success) {
  ElMessage.success('导出成功')
} else {
  ElMessage.error('导出失败：' + result.error)
}
```

**平台行为差异**：
- Electron/Web：触发浏览器下载
- Capacitor：保存到 Documents 目录

### 4.2 公用代码编写原则

#### ✅ 必须遵守

1. **无平台特定代码**
   ```javascript
   // ✅ 正确：纯 JavaScript，无 DOM 操作

   }
   ```

   ```javascript
   // ✅ 正确：使用适配层
   ```


## 五、平台差异处理指南

### 5.1 需要适配的平台差异

| 功能差异 | Electron | Capacitor | Web | 处理方式 |
|---------|---------|-----------|-----|---------|
| **存储** | localStorage | Preferences | localStorage | `storage` 适配层 |
| **数据库** | sql.js | SQLite Plugin | 不支持 | `database` 适配层 |
| **文件导出** | Blob下载 | Filesystem | Blob下载 | `filesystem` 适配层 |
| **网络检测** | navigator | Network Plugin | navigator | `network` 适配层 |
| **右键菜单** | 支持 | 不支持 | 不支持 | `v-if="isDesktop"` |
| **拖拽交互** | 鼠标事件 | 触摸事件 | 鼠标+触摸 | 条件判断 |
| **布局** | 侧边栏 | TabBar | 响应式 | CSS媒体查询(推荐) 或 `v-if` 条件渲染 |

### 5.2 DOM 操作差异处理

#### ❌ 禁止直接使用

```javascript
// ❌ 错误：直接操作 DOM
document.documentElement.setAttribute('data-theme', 'dark')
window.innerWidth
window.matchMedia('(prefers-color-scheme: dark)')
```

#### ✅ 正确做法

```javascript
// ✅ 正确：在适配层中封装
// src/shared/platform/dom.js（新增）
export const dom = {
  setTheme(theme) {
    if (platformInfo.isElectron || platformInfo.isWeb) {
      document.documentElement.setAttribute('data-theme', theme)
    } else {
      // Capacitor: 使用 CSS 变量或其他方式
      document.body.classList.toggle('dark-theme', theme === 'dark')
    }
  },

  getWindowWidth() {
    return window.innerWidth
  },

  isDarkMode() {
    if (platformInfo.isCapacitor) {
      // Capacitor: 使用其他方式检测
      return false
    }
    return window.matchMedia('(prefers-color-scheme: dark)').matches
  }
}
```

### 5.4 移动端UI布局最佳实践（重要！）

#### 方案对比：CSS媒体查询 vs v-if条件渲染

**场景分析**：
- **纯布局样式调整** → ✅ 推荐 CSS媒体查询（性能更好）
- **功能逻辑差异** → ✅ 必须使用 v-if条件渲染
- **DOM结构完全不同** → ✅ 必须使用 v-if条件渲染

#### ✅ 推荐方案1：CSS媒体查询（纯布局调整）

**适用场景**：组件结构相同，仅样式不同

**优势**：
- ✅ 性能最优：无需JavaScript判断，CSS引擎直接处理
- ✅ 代码简洁：单一DOM结构，维护成本低
- ✅ 响应式友好：窗口大小变化时自动适配
- ✅ 开发效率高：无需编写平台判断逻辑

**实现示例**：

## 七、常见问题与解决方案

### 7.1 存储异步问题

**问题**：Store 初始化时无法读取存储值

```javascript
// ❌ 错误
const storedTheme = localStorage.getItem('theme') // 已删除
const theme = ref(storedTheme)
```

**解决**：异步加载 + 默认值

```javascript
// ✅ 正确
const theme = ref('light') // 默认值

onMounted(async () => {
  const stored = await storage.get('theme')
  if (stored) theme.value = stored
})
```

### 7.2 平台检测时机问题

**问题**：Server Side Rendering 时 `window` 不存在

**解决**：安全检测

```javascript
// ✅ 正确
export const isElectron = typeof window !== 'undefined' && window.electronAPI !== undefined
```

### 7.3 数据库未初始化问题

**问题**：调用 `database.query()` 时报错 "数据库未初始化"

**解决**：应用启动时初始化

```javascript
// main.js
import { database } from '@shared/platform'

// 应用启动时初始化数据库
database.init().then(() => {
  console.log('数据库已就绪')
}).catch(err => {
  console.error('数据库初始化失败:', err)
})
```

### 7.4 Android 构建失败

**问题**：`npx cap run android` 报错

**排查步骤**：
1. 检查 Android Studio 是否安装
2. 检查 Android SDK 版本（最低 API 22）
3. 检查 Gradle 配置：`android/app/build.gradle`
4. 清理构建：`cd android && ./gradlew clean`

## 八、新增原生能力适配器示例

### 8.1 添加通知功能适配器

```javascript
// src/shared/platform/notification.js
import { LocalNotifications } from '@capacitor/local-notifications'
import { isElectron, isCapacitor } from './index'

export const notification = {
  async schedule(title, body, scheduleTime) {
    if (isElectron) {
      // Electron: 使用 Electron Notification API
      // 需在 main.js 中实现通知功能
      new Notification(title, { body })
    } else if (isCapacitor) {
      // Capacitor: 使用 LocalNotifications 插件
      await LocalNotifications.schedule({
        notifications: [{
          title,
          body,
          id: Date.now(),
          schedule: { at: scheduleTime }
        }]
      })
    } else {
      // Web: 使用浏览器 Notification API
      if (Notification.permission === 'granted') {
        new Notification(title, { body })
      } else {
        await Notification.requestPermission()
      }
    }
  }
}
```

### 8.2 在 index.js 中导出

```javascript
// src/shared/platform/index.js
export { notification } from './notification'
```

## 十一、实际改造经验总结（新增）

### 11.1 移动端UI改造实战经验

#### 改造项目概述

**改造时间**: 2026-07-03

**改造范围**: 全部视图组件的移动端竖屏布局优化

**改造组件**:
- ✅ DayView (记录视图) - 核心改造
- ✅ WeekView (周视图) - 垂直堆叠布局
- ✅ MonthView (月视图) - 统计卡片纵向排列
- ✅ StatsView (统计视图) - TabBar优化
- ✅ SettingsView (设置界面) - 垂直布局

#### 关键改造点

**1. DayView创新布局设计**

**改造前问题**:
- 移动端简单压缩PC端布局,便签栏占据过多空间
- 时间网格被严重压缩,操作困难

**改造方案**:
- 便签栏移至右侧,压缩为56px窄条
- 时间轴刻度保持左侧,宽度不变(50px)
- 时间网格占据中间主要空间

**技术选择**: ✅ CSS媒体查询

**实现要点**:
```scss
@media screen and (max-width: 900px) {
  .task-pool {
    order: 3; // 移到右侧
    width: 56px;
    border-left: 1px solid var(--border-light);
  }
  
  .day-view-main {
    order: 1; // 时间网格在左侧
  }
}
```

**改造效果**:
- ✅ 便签栏不干扰时间网格操作
- ✅ 时间轴刻度保持可读性
- ✅ 创新设计符合移动端竖屏习惯

**2. WeekView纵向堆叠布局**

**改造前问题**:
- 7列横向并排,在竖屏上几乎无法使用

**改造方案**:
- 改为纵向堆叠,每天独立卡片
- 添加日期标题显示

**实现要点**:
```scss
@media screen and (max-width: 900px) {
  .week-body {
    flex-direction: column; // 纵向排列
    gap: 12px;
  }
  
  .day-column {
    width: 100%;
    
    .day-title-mobile {
      display: flex; // 仅移动端显示
    }
  }
}
```

**3. MonthView统计卡片纵向排列**

**改造方案**:
- 统计卡片从3列改为单列纵向堆叠
- 双图表横向排列改为纵向排列
- 日历网格保持7列(日历本身需要)

**实现要点**:
```scss
@media screen and (max-width: 900px) {
  .stats-cards {
    grid-template-columns: 1fr; // 单列
  }
  
  .charts-row {
    grid-template-columns: 1fr; // 单列
  }
}
```

#### 改造经验总结

**✅ 成功经验**:

1. **CSS媒体查询优先**
   - 纯布局调整时,CSS方案性能最优
   - 避免不必要的JavaScript判断
   - 响应式切换更流畅

2. **保持单一DOM结构**
   - 代码维护成本低
   - 减少重复代码
   - 便于后续优化

3. **响应式断点统一**
   - 建议统一使用900px断点
   - 避免使用不一致的断点值(如799px)

4. **触摸区域优化**
   - 按钮高度≥44px(iOS规范)
   - 增加视觉反馈
   - 保持手势功能

**⚠️ 需要注意的问题**:

1. **Capacitor CSS变量兼容性**
   - 需要在Android真机测试CSS变量支持
   - 如有问题,可改用具体颜色值

2. **触摸手势流畅度**
   - Web端测试可能流畅,真机可能有差异
   - 需要实际Android设备验证

3. **布局切换时机**
   - 900px断点可能导致某些平板设备误判
   - 可根据实际使用场景调整断点
